# First real job: connection and capability check

This checklist is an operator/agent procedure, not evidence that a live test has run. Run it in the selected hosted environment with the user's test authorization. Do not use the target game repository as a mandatory environment base.

1. Open Officina and confirm `AGENTS.md` plus the five skills are available. If automatic discovery is unavailable in that client, explicitly read the relevant skill files. Record the actual tool/runtime versions. No fixed environment ID is part of this repository.
2. Create a job directory and brief. Confirm Blender by invoking its version and an authorized minimal file creation/reopen check. Check GPU only if the job requires it; CPU-only results do not prove GPU readiness.
3. Resolve the designated Discord thread. Send one labelled connection-test message and record its confirmed message ID. Ask one numbered question and receive an attributable answer through the configured read route. Posting alone fails the bidirectional acceptance check.
4. Transfer a small nonsecret sample through Synergos in both directions. Compare byte length and SHA-256 on the recipient. Use the current broker/client, not speculative endpoints. If no suitable Synergos route exists, record the exact reason and perform the same check in the approved Drive folder. Never change folder sharing just to make the check pass.
5. Give a separate critic a brief and intentionally imperfect small artifact, without explaining the intended defect. Record the evidence it inspected and whether a follow-up checks a corrected revision. If no separate reviewer is available, record independent review unavailable.
6. Proceed to the user's actual modelling request only after relevant inputs and capabilities are ready. For “ビル一棟作って”, request existing three-view drawings/concept art, or permission to generate a draft reference. Do not spend a full production budget before this checkpoint.

Record each result as passed / failed / not run with evidence. Do not treat a repository being available, a cloud login or a successful tool invocation as completion of the full workflow.
